# MAX Chat — GREEN-API

Тестовое задание на позицию **Frontend React Developer**.

Приложение представляет собой минимальный веб-чат для отправки и получения текстовых сообщений в **MAX** через **GREEN-API**. В качестве визуального прототипа использован интерфейс [MAX Web](https://web.max.ru/).

## Техническое задание

**Время на выполнение:** 5 дней.

### Требования

1. Разработать пользовательский интерфейс для отправки и получения сообщений в MAX.
2. Использовать сервис [GREEN-API](https://green-api.com/max).
3. Реализовать отправку и получение **только текстовых сообщений**.
4. В качестве прототипа интерфейса использовать внешний вид чата [MAX Web](https://web.max.ru/).
5. Интерфейс должен быть максимально простым и содержать минимально необходимый набор функций.
6. Отправку сообщений реализовать методом [SendMessage](https://green-api.com/v3/docs/api/sending/SendMessage/).
7. Получение сообщений реализовать через [HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/).
8. Использовать React.

### Ожидаемый сценарий

1. Пользователь открывает приложение и вводит `idInstance` и `apiTokenInstance` из GREEN-API.
2. Пользователь вводит номер телефона получателя и создаёт чат.
3. Пользователь отправляет текстовое сообщение в MAX.
4. Получатель отвечает в мессенджере MAX.
5. Ответ появляется в веб-чате без перезагрузки страницы.

## Что реализовано

- авторизация по `idInstance` и `apiTokenInstance`;
- проверка состояния инстанса через `GetStateInstance`;
- защита страницы чатов от неавторизованного доступа;
- создание чата по номеру телефона;
- проверка наличия аккаунта через `CheckAccount`;
- защита от создания дублей одного чата;
- отправка текстовых сообщений через `SendMessage`;
- поддержка многострочных сообщений;
- `Enter` — отправка, `Shift + Enter` — перенос строки;
- ограничение сообщения до 4000 символов;
- отдельный черновик для каждого чата;
- отображение сообщения сразу после отправки со статусом `Отправляется`;
- отображение статусов исходящего сообщения:
  - `Отправляется`;
  - `Принято в очередь`;
  - `Доставлено`;
  - `Прочитано`;
  - ошибка отправки;
  - неопределённый результат при сетевой ошибке;
- получение событий через `ReceiveNotification`;
- подтверждение обработанных событий через `DeleteNotification`;
- получение входящих текстовых сообщений;
- автоматическое появление нового чата при входящем сообщении от неизвестного собеседника;
- защита от повторного добавления одного и того же входящего сообщения;
- long polling с автоматическим восстановлением после временных ошибок;
- проверка настроек уведомлений GREEN-API через `GetSettings`;
- повторная проверка некорректных настроек раз в 15 секунд до их исправления;
- предупреждения пользователю при неправильных настройках уведомлений или проблемах polling;
- отмена незавершённых запросов при выходе из аккаунта;
- адаптивный интерфейс для desktop/mobile;
- unit/component-тесты для API, stores, форм, сообщений и основных пользовательских сценариев.

## Как работает приложение

### Авторизация

После ввода данных приложение выполняет `GetStateInstance`.

```text
idInstance + apiTokenInstance
          ↓
   GetStateInstance
          ↓
     authorized
          ↓
        /chat
```

Учетные данные хранятся только в состоянии приложения и очищаются при выходе.

### Создание чата

Перед созданием чата номер нормализуется и проверяется. Затем выполняется `CheckAccount`.

```text
номер телефона
      ↓
нормализация
      ↓
 CheckAccount
      ↓
    chatId
      ↓
 новый чат
```

В текущей реализации форма поддерживает российские номера (`7XXXXXXXXXX`) и белорусские (`375XXXXXXXXX`). Российский номер, введённый через `8`, автоматически преобразуется в формат с `7`.

### Отправка сообщения

После нажатия Enter сообщение сразу добавляется в интерфейс со статусом `sending`, после чего выполняется `SendMessage`.

```text
MessageComposer
      ↓
ChatStore.sendMessage()
      ↓
локальное сообщение: sending
      ↓
SendMessage
      ↓
получен idMessage
      ↓
queued
```

`id` локального сообщения используется как стабильный React key. `idMessage`, полученный от GREEN-API, используется для дальнейшего сопоставления статусов доставки.

Если сервер явно отклонил запрос, сообщение получает статус ошибки. Если произошёл timeout или сетевой сбой и невозможно понять, успел ли сервер принять сообщение, используется состояние `unknown`, чтобы не утверждать ошибочно, что сообщение точно не было отправлено.

### Статусы сообщений

После успешного `SendMessage` приложение продолжает получать события через HTTP API.

```text
queued
  ↓
outgoingMessageStatus
  ├─ delivered → Доставлено
  ├─ read      → Прочитано
  └─ failed    → Ошибка
```

Статусы сопоставляются с локальным сообщением по `idMessage`.

Также учтён race condition, когда статус от GREEN-API может прийти раньше, чем завершится HTTP-запрос `SendMessage`: такие статусы временно сохраняются и применяются после получения `idMessage`.

### Получение сообщений

После успешной авторизации автоматически запускается long polling.

```text
ReceiveNotification
        ↓
получено событие
        ↓
handleNotification
   ├─ incomingMessageReceived
   │        ↓
   │  добавить сообщение
   │
   └─ outgoingMessageStatus
            ↓
      обновить статус
        ↓
DeleteNotification
        ↓
следующий ReceiveNotification
```

Поддерживаются входящие `textMessage` и `extendedTextMessage`.

Если приходит неподдерживаемый тип сообщения, приложение показывает текст-заглушку. Если уведомление содержит некорректные данные и его невозможно отобразить, пользователь получает предупреждение, а очередь продолжает обрабатываться.

## Настройки GREEN-API

Для работы HTTP polling поле **«Адрес отправки уведомлений (URL)» должно быть пустым**.

Рекомендуемые настройки инстанса:

| Настройка | Значение |
| --- | --- |
| Адрес отправки уведомлений (URL) | пусто |
| Заголовок авторизации для отправки уведомлений | пусто |
| Получать уведомления о входящих сообщениях и файлах | ВКЛ |
| Получать уведомления о сообщениях, отправленных с телефона | ВКЛ |
| Получать уведомления о сообщениях, отправленных с API | ВКЛ |
| Получать уведомления о статусах отправленных сообщений | ВКЛ |
| Получать уведомления об удалённых сообщениях | ВЫКЛ |
| Получать уведомления о редактированных сообщениях | ВЫКЛ |
| Получать уведомления об изменении состояния авторизации | ВЫКЛ |
| Получать уведомления об опросах | ВЫКЛ |

При старте polling приложение вызывает `GetSettings`. Если обязательные настройки выключены, над чатом появляется предупреждение. Пока проблема существует, настройки перепроверяются каждые 15 секунд; после исправления предупреждение исчезает автоматически.

```text
src/
├── app/
│   ├── (init)/
│   │   ├── guards/          # AuthGuard
│   │   ├── layout/          # общий layout приложения
│   │   └── providers/       # Auth/Chat/UI providers
│   └── (router)/            # маршруты /chat и /connection
│
├── pages/
│   ├── connection/          # вход и выход из GREEN-API
│   └── chat/
│       ├── api/             # chatApi и обработка ошибок
│       ├── model/           # типы, схемы, phone helpers
│       ├── store/           # ChatStore
│       └── ui/              # список чатов, сообщения, composer, modal
│
└── shared/
    ├── api/green-api/       # общий Axios client и типы GREEN-API
    ├── auth/                # AuthStore, AuthProvider, authApi
    ├── config/              # env и тема Ant Design
    └── lib/                 # общие утилиты
```

Routing построен на Next.js App Router. Бизнес-страницы находятся в `src/pages`, а файлы маршрутов в `src/app/(router)` только подключают соответствующие page-модули.

## Локальный запуск

### Требования

- Node.js `>= 22`;
- npm `>= 10`;
- созданный и авторизованный инстанс GREEN-API для MAX.

### 1. Установить зависимости

```bash
npm ci
```

### 2. Создать `.env.local`

Можно скопировать пример:

```bash
cp .env.example .env.local
```

Для Windows PowerShell:

```powershell
Copy-Item .env.example .env.local
```

Пример:

```env
NEXT_PUBLIC_GREEN_API_URL=https://3100.api.green-api.com
```

При необходимости укажите API host своего инстанса GREEN-API.

### 3. Запустить приложение

```bash
npm run dev
```

Открыть:

```text
http://127.0.0.1:3000
```

Корневой маршрут перенаправит пользователя на `/connection`.

## Как проверить основной сценарий

1. Создать и авторизовать инстанс MAX в GREEN-API.
2. Включить необходимые уведомления из раздела выше.
3. Запустить приложение.
4. Ввести `idInstance` и `apiTokenInstance`.
5. Нажать **«Войти»**.
6. Создать чат по номеру телефона пользователя MAX.
7. Отправить текстовое сообщение.
8. Проверить смену статуса `Отправляется → Принято в очередь → Доставлено`.
9. Открыть сообщение на стороне получателя и проверить статус `Прочитано`.
10. Ответить из MAX и убедиться, что входящее сообщение появилось в веб-чате без обновления страницы.

## Ограничения

Проект намеренно оставлен минимальным в соответствии с тестовым заданием.

Не реализованы:

- отправка файлов, изображений, аудио и других вложений;
- история сообщений из MAX до запуска приложения;
- поиск по чатам и сообщениям;
- звонки;
- реакции;
- редактирование и удаление сообщений;
- постоянное хранение чатов и учётных данных в браузере.

Чаты, сообщения и авторизация хранятся в памяти приложения, поэтому после полного обновления страницы локальное состояние начинается заново.

## Используемые методы GREEN-API

- `GetStateInstance` — проверка подключения инстанса;
- `CheckAccount` — проверка номера и получение `chatId`;
- `SendMessage` — отправка текста;
- `ReceiveNotification` — получение событий;
- `DeleteNotification` — подтверждение обработанного события;
- `GetSettings` — проверка настроек уведомлений.
